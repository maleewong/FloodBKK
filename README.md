# FloodBKK: ระบบระบายน้ำ กทม. 50 เขต (ต้นแบบวิจัย)

หน้าเว็บแสดงสถานการณ์ระบายน้ำ กทม. แผนที่คลองและแม่น้ำ และโมเดลจัดสรรการระบาย (min-cost flow และ LP หลายช่วงเวลา)
ข้อมูลจากสำนักการระบายน้ำ กรุงเทพมหานคร (weather.bangkok.go.th) ดึงผ่านหน้าเว็บสาธารณะเพื่อการศึกษา ไม่ใช่ API ทางการ
โครงข่ายคลองจาก OpenStreetMap (© OpenStreetMap contributors, ODbL)

- `bkk_drainage.html`: ภาพรวม แผนที่คลอง/แม่น้ำ สถานะสถานีวัดน้ำ น้ำท่วมถนน ฝน การสูบน้ำ
- `bkk_model.html`: สถานการณ์ปัจจุบัน (ไม่มีฝนเพิ่ม) เส้นทางระบายตามแผน LP 30 วัน คำแนะนำ สูบที่ไหน คอขวด ใช้เวลากี่วัน
- `bkk_forecast.html`: ฝนคาดการณ์ 48 ชม. (Open-Meteo + ensemble ECMWF) ควรพร่องน้ำคลองไหน เดินเครื่องสูบเมื่อไร พร้อมกรณี P90 และกรณีสุดขีด
- `bkk_ponding.html`: จำลองสถานการณ์ สูบน้ำท่วมขังในชุมชน ปรับจำนวนเครื่อง การแบ่งความจุคลอง ขยายคอขวด แล้วดูผล จากรายงาน Traffy Fondue + DEM ประมาณบริเวณที่ท่วมและปริมาณน้ำ ตรวจความใหม่ของรายงาน แนะนำจุดตั้งเครื่องสูบ คลองที่ควรสูบลง และปลายทาง (รวมทางน้ำนอกเขต กทม.)

## เว็บออนไลน์ (GitHub Pages)

GitHub Actions (`.github/workflows/update.yml`) รันทุก 2 ชั่วโมง: ดึงข้อมูลล่าสุด คำนวณแผนใหม่ แล้วเผยแพร่ทุกหน้า
ถ้าดึงข้อมูลไม่สำเร็จ จะเผยแพร่จากข้อมูลชุดล่าสุดที่มีอยู่ (เวลาข้อมูลแสดงที่มุมขวาบนของหน้า)

ตั้งค่าครั้งแรก: Settings → Pages → Build and deployment → Source เลือก **GitHub Actions**
แล้วไปที่แท็บ Actions → update-and-publish → **Run workflow**

## ใช้ในเครื่อง (Windows)

- `update.bat`: ดึงข้อมูลล่าสุดและสร้างทุกหน้าใหม่ (ราว 3–8 นาที) แล้วกด F5 ในหน้าเว็บ
- `start.bat --auto 60` (ไม่บังคับ): เปิดเว็บที่ http://127.0.0.1:8765 และอัปเดตเองทุก 60 นาทีขณะเปิดหน้าต่างค้างไว้
- ต้องมี Python 3 ส่วนแผนระบาย 30 วันต้องติดตั้งเพิ่ม `pip install -r requirements.txt`

## โครงสร้าง

```
scripts/update.py        ดึงข้อมูล -> build.py -> build_model.py -> plan_lp.py -> forecast_lp.py -> build_outer.py -> build_ponding.py -> render.py
scripts/plan_lp.py       LP หลายช่วงเวลา (HiGHS) แผนระบาย 30 วันเมื่อไม่มีฝนเพิ่ม
scripts/forecast_lp.py   LP ช่วงละ 3 ชม. 48 ชม. ตามฝนคาดการณ์ แผนพร่องน้ำเทียบกับสูบแบบเดิม
scripts/build_ponding.py จุดท่วมขังจาก Traffy + DEM (บริเวณที่ต่ำกว่าระดับน้ำที่รายงาน) + เซนเซอร์น้ำท่วมถนน
scripts/build_outer.py   ต่อทางออกขอบเขตไปตามคลองนอกเขต (OSM) ถึงทะเล/แม่น้ำ (แสดงผลเท่านั้น)
scripts/model_core.js    โมเดล min-cost flow ที่รันในหน้าเว็บ (solver.js)
scripts/build_network.py สร้างกราฟคลองจาก OSM (รันครั้งเดียว) แล้ว adjust_network.py ปรับความกว้างคลองตามรายงาน 2557 + อุโมงค์บึงหนองบอน  scripts/calibrate.py  ปรับเทียบจากข้อมูลย้อนหลัง
data/                    ข้อมูลตั้งต้นและข้อมูลดิบ (ไฟล์ .csv .sqlite และ html สร้างใหม่ทุกครั้ง ไม่เก็บใน repo)
```

ผลโมเดลขึ้นกับสมมติฐาน (ความจุคลอง ทางออกขอบเขต พื้นที่เก็บน้ำ) ซึ่งระบุไว้ในหน้าโมเดล ใช้เปรียบเทียบทางเลือก ไม่ใช่พยากรณ์ทางการ
